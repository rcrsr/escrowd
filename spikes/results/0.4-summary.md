# 0.4 Per-scope routing and read gating: go

Oct 3, 2026. Spike: `spikes/04-routing/` (one FUSE mount whose top-level directories are scopes, each a copy-on-write view with its own upper; read gate; ledger) plus `python/escrow_shim.py` (stdlib only). Per-host logs: `0.4-*.log`.

| Host | bwrap | Python | Checks passed |
| --- | --- | --- | --- |
| WSL2 dev host (kernel 6.18.40) | system 0.9.0 | 3.14.8 | 17 / 17 |
| Debian 13 (6.12.95) | system 0.12.0 | system | 17 / 17 |
| Fedora 44 (6.19.10, SELinux enforcing) | system 0.12.0 | system | 17 / 17 |
| Ubuntu 24.04 (6.8.0) | escrowd bwrap + profile | system | 17 / 17 |

The checks:

1. **Routing**: two scopes run as two asyncio tasks on one thread, interleaved with `await asyncio.sleep(0)`, writing the same paths (absolute path, relative path, pathlib) and each running `bash -c "echo … > build.log"`. Every write lands in its own scope's upper; none crosses; each scope reads back its own README and build output; the base stays byte-identical.
2. **Per-scope inodes**: the same lower file has a different inode number in each scope (scope index << 48 | lower st_ino), so the kernel never shares page cache or writeback-cached data between scopes.
3. **Read gate**: `open(".env")` in-process raises `PermissionError` (EACCES); `cat .env` in a scope subprocess fails with `Permission denied`; both denials are in the ledger with the scope; allowed reads still work.
4. **Attribution in the ledger**: subprocess writes appear as `scope=a op=create path=build.log` and `scope=b …`, attributed by path alone.
5. **Flush before decision**: a 4 MiB write held by the writeback cache reaches the daemon in full after the scope flush (fsync of the scope's open files), with the file still open; `close()` alone also delivers every byte.

Findings:

1. **syncfs is not a flush barrier on plain FUSE.** Before any flush the daemon had 0 to 3.3 MiB of 4 MiB. After `syncfs` alone it had all 4 MiB in 7 of 10 measurements and 0, 3,780,608 or 3,932,160 bytes in the other 3. FUSE mounts other than virtiofs have no `sync_fs`, so `syncfs` starts writeback without waiting for the daemon. `fsync` and `close` wait (`fuse_sync_writes`) and delivered every byte in every run. Scope close must fsync every open file of the scope; files closed by exited subprocesses are already flushed by `close`.
2. **Inode numbers must be scoped** once one mount serves several scopes; 0.3's bare lower st_ino would alias the same file across scopes.
3. **The ContextVar shim works across asyncio tasks** for builtins `open`, `os.*` and pathlib, and `asyncio.create_subprocess_exec` goes through the patched `subprocess.Popen`, so subprocesses inherit the task's scope.
4. Limits carried into phase 1: scopes are created by `mkdir` in the mount root (a spike control plane, not the RPC socket); the read rule is hard-coded (`.env`); the SDK tracks only files opened through the patched `open`.
