# 0.6 Overhead benchmark: go for plain FUSE

Oct 3, 2026. Spike: `spikes/06-bench/` (`run.sh`, `summarize.py`, committed `pnpm-lock.yaml`). Logs: `0.6-bench-ubuntu-24.04.log`, `0.6-wsl-dev-host.log`.

Workload: express `v5.2.1` (8,785 files in `node_modules`, 64 MB; 1,238 mocha tests). Offline: a local git mirror, a prefilled pnpm store and metadata cache. Each run starts from fresh directories and a fresh mount.

- **A, agent pipeline from an empty project**: `git clone`, `pnpm install --frozen-lockfile --offline` (copy import), `pnpm test`. In FUSE modes every write lands in the upper.
- **B, tree already in the base**: `git status`, read every file (`tar cf - . | wc -c`), `pnpm test`. Every read goes through the view cold.

Modes: **native**; **bwrap** (the sandbox, no FUSE); **fuse** (spike 0.3 view: unprivileged cache flags, 1 request thread, 1 s entry/attr cache); **fuse-cache** (adds `FOPEN_KEEP_CACHE` and a 60 s cache); **fuse-tuned** (fuse-cache plus 8 request threads); **bindfs** 1.14.7 (a libfuse mirror without copy-on-write: a floor for plain FUSE cost). All modes pass all 1,238 tests in every run.

## Verdict

1. **Phase 2 metric met without a root helper.** The test suite under the view runs at 1.01–1.16× of native (VM) and 1.06× (dev host); the full agent pipeline (A) totals 1.21–1.25×. Both are under the 1.5× target.
2. **The sandbox is free.** bwrap without FUSE is within noise of native (0.82–0.94× totals).
3. **Cold metadata and read-heavy operations are expensive through any FUSE.** Reading every file of the tree costs 23× in bindfs and 28–33× in the spike; `pnpm install` 5× in bindfs and 6–9× in the spike; `git status` 5×. Workload B totals 1.6–2.0× in the VM, bindfs included (1.61×). This is the FUSE round trip per lookup, open and read, not the spike's thread count.
4. **Keep-cache and threads did not help these workloads.** Each run reads each file once on a fresh mount, so `FOPEN_KEEP_CACHE` has nothing to reuse; 8 threads changed little and the spike's global lock serializes them anyway.
5. **Phase 2 optimization targets**, in order: avoid per-call `/proc/self/fd/<fd>/<path>` walks (use `openat`/`fstatat` on cached directory fds); `READDIRPLUS` so listings return attributes; finer locks so threads help; keep-cache for repeated reads within a scope. Kernel passthrough (root helper) stays the fallback for the data path only; it would not remove lookup and open round trips.

## Findings

1. **pnpm needs a writable store and metadata cache.** pnpm 12 fails offline installs with a read-only store (`ERR_PNPM_NO_OFFLINE_TARBALL`) and needs its metadata cache (`$XDG_CACHE_HOME/pnpm`) for `--offline`. Package stores are shared writable state outside the project: escrowd must bind them writable (unescrowed) or route them through FUSE, as the proposal's "shared state outside the project" risk says.
2. **bindfs as a regular user needs `--no-allow-other`**; without it the mount fails and a benchmark silently measures a plain directory. `run.sh` now refuses to time a run whose mount failed.
3. Run-to-run noise in the VM's test step is about ±25%; medians over 7 runs are used.
