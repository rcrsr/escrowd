# 0.3 Copy-on-write semantics: go

Oct 3, 2026. Spike: `spikes/03-cow/` (overlay FUSE view: read-only lower, upper staging directory, whiteouts, opaque directories). Per-host logs: `0.3-*.log`.

| Host | bwrap | Checks passed |
| --- | --- | --- |
| WSL2 dev host (kernel 6.18.40) | system 0.9.0 | 14 / 14 |
| Debian 13 (6.12.95) | system 0.12.0 | 14 / 14 |
| Fedora 44 (6.19.10, SELinux enforcing) | system 0.12.0 | 14 / 14 |
| Ubuntu 24.04 (6.8.0) | escrowd bwrap + profile | 14 / 14 |

The checks:

1. **Base untouched**: a fingerprint of the base (every entry including `.git`, with modes, sizes, mtimes and content hashes) is identical before and after all work in the view.
2. **Behaves as native**: one scenario (append, rename, delete file, `rm -r` dir, recreate dir, `mkdir -p`, chmod, truncate, symlink, atomic-rename editor save, vim-style backup save, `git add` and commit) runs on a native copy and in the view. Tree listing, `git status --porcelain` and `git log` tree hashes match.
3. **Inodes**: a lower file shows its lower st_ino, keeps it through copy-up, and keeps it through rename.
4. **Whiteouts and opaque dirs**: deleted lower entries are hidden; a deleted then recreated directory shows none of its lower contents.
5. **Directory rename**: renaming a lower-backed directory returns EXDEV (as overlayfs does without redirects); `mv` falls back to copy and delete and succeeds.
6. **Upper**: holds every change and no copy of untouched files.

Findings:

1. A path-keyed inode table must survive hard links: git writes objects as `link(tmp, final)` then `unlink(tmp)`. Dropping the inode's only path on unlink made every new object unreadable (`is not a valid object`).
2. Using the lower st_ino as the FUSE inode keeps numbers stable through copy-up and rename, and across remounts for entries still at their lower path. Upper-only entries use a separate range (2^56 and up) and are not stable across remounts.
3. Limits carried into phase 1: whiteouts and opaque marks live in memory and are lost when the daemon restarts; copy-up copies whole files; lower-backed directory renames rely on the EXDEV fallback.
4. Lima home mounts (9p `cache=loose` and sshfs alike) serve stale or half-updated files after host edits; run `sudo sysctl -q vm.drop_caches=3` in every VM before each run.
