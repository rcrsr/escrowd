# 0.7 AgentFS embed decision: rejected

Oct 3, 2026. Spike: `spikes/07-agentfs/` (434-line fuser adapter over `agentfs_sdk::filesystem::OverlayFS`, same command line as spike 0.3). Logs: `0.7-wsl-dev-host.log` (crates.io 0.6.4), `0.7-wsl-dev-host-head.log` (repo HEAD `0a014eb`), `0.7-debian-13-system-bwrap.log`.

## Result: 6 / 14 of spike 0.3's checks pass, on every host and both versions

| Check | Result | Cause |
| --- | --- | --- |
| mount, deleted lower file hidden, recreated dir hides lower contents, mv of lower dir, base byte-identical, no copy of untouched files | pass | |
| inode equals lower inode; stable across copy-up; stable across rename | fail, by design | AgentFS numbers inodes from an in-memory counter; copy-up does keep the number (measured: 2 before and after a write). Our design uses the lower st_ino instead. |
| upper holds staged changes | fail, by design | The delta lives in SQLite (`delta.db`), not as files. |
| scenario runs, git status, tree and git log match native | **fail, defect** | Renaming a lower-backed file leaves AgentFS's inode maps stale. |

**The defect**: after `mv stable.txt stable2.txt`, the listing shows `stable2.txt` and `stat` works, but `open` fails with ENOENT; after the entry cache expires, reads alternate between the content and EIO. `OverlayFS::rename` copies up and writes whiteouts but never updates `inode_map`, `path_map` or `reverse_map`, so the inode the kernel holds still resolves to the old path. AgentFS's own FUSE front end calls `rename` the same way and caches entries forever (`TTL = Duration::MAX`), so it is exposed too. git's lockfile-then-rename writes hit it on every commit.

## Cost of embedding

| | Spike 0.3 (ours) | AgentFS adapter |
| --- | --- | --- |
| Our code | 822 lines | 434 lines + the crate |
| Transitive crates | 4 | 246 (HEAD adds OpenSSL and libgit2) |
| Release binary | 0.9 MB | 15.9 MB |
| Store engine | the filesystem | Turso (beta), async on tokio |
| 0.3 checks | 14 / 14 | 6 / 14 |

## Decision

Reject AgentFS as escrowd's store; keep escrowd's own overlay (spike 0.3 lineage). Embedding would save about 400 lines while adding a beta database engine, 242 extra crates, an upstream rename defect that breaks git, and an inode scheme that is not stable across remounts.

Kept from AgentFS, already in our design: pre-opening the base, an origin inode mapping through copy-up, whole-file copy-up, the unprivileged writeback-cache init flags, and a per-scope store for staged state. Phase 1 can persist whiteouts and the manifest in plain SQLite (for example `rusqlite`) without Turso.

The rename defect is worth an upstream issue; filing it is outward-facing and waits for a decision.
