# 0.5 Snapshot at open: go, with a recommended mechanism to confirm

Oct 3, 2026. Spike: `spikes/05-snapshot/` (`setup-volumes.sh` for 2 GB loopback XFS and btrfs volumes, `run.sh`, `summarize.py`). Log: `0.5-bench-ubuntu-24.04.log`. Host: benchmark VM, Ubuntu 24.04, kernel 6.8.0, 4 vCPUs; every mechanism runs unprivileged.

Tree: express `v5.2.1` after `pnpm install`: 9,116 entries, 69–77 MB.

## Isolation (8 / 8 checks pass)

For each snapshot mechanism, a spike 0.3 copy-on-write view uses the snapshot as its lower. After the view opens, the base gets a commit (a file changed, one deleted, one added). The view still shows the pre-commit state on ext4 (full copy), XFS (copy, reflink) and btrfs (copy, reflink, subvolume snapshot).

Without a snapshot (live lower), the view shows the commit: no isolation. A per-file version check (`st_ino`, size, mtime, ctime) detects the change at commit time.

## Findings

1. **Reflink saves space, not time.** On XFS and btrfs, a reflink copy takes as long as a plain copy (150–210 ms), because the cost is creating 9,116 inodes, not copying 70 MB. Plain `cp -a` already reflinks there (coreutils 9 defaults to `--reflink=auto`).
2. **Copy-based snapshots scale with entry count**: 13–23 µs per entry here, so a 100,000-entry repo would take roughly 1.3–2.3 s per scope open (extrapolated, not measured). Too slow for a scope per tool call.
3. **btrfs subvolume snapshots are constant-time** (8 ms create, 3 ms delete, 0 MB), unprivileged with the `user_subvol_rm_allowed` mount option, but only when the project is itself a btrfs subvolume.
4. **A version check is cheap**: stat of every entry takes 16–19 ms; checking only the files a scope touched costs less.

## Recommendation (to confirm)

Isolate scopes from each other without per-open copies, and detect everything else:

1. **Pre-images at commit.** escrowd applies every scope commit through its journal, so before overwriting or deleting a base file it saves the old version into a base generation layer. Scopes opened earlier keep reading through their generation. Cost follows commit size, on any filesystem. Not built in phase 0; phase 1 must prove it.
2. **Per-file version check at commit** for writers outside escrowd (an editor, git on the host): record each file's version on first access, compare at commit, and apply the conflict policy (default: discard). Without a snapshot these external edits are visible mid-scope; they are detected, not hidden.
3. **btrfs subvolume snapshot as an optional fast path** when the project is a subvolume: full isolation, including from external writers, at 8 ms per open.

Rejected as the default: copy or reflink snapshot at every open (linear in entry count; on ext4 also a full copy of the tree per scope).
