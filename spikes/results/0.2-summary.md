# 0.2 FUSE in bwrap over `$PROJECT`: go

Oct 3, 2026. Spike: `spikes/02-fuse-bwrap/` (mirroring FUSE view, `run.sh` checks, Ubuntu AppArmor profile). Per-host logs: `0.2-*.log`.

| Host | bwrap | Checks passed |
| --- | --- | --- |
| WSL2 dev host (kernel 6.18.40) | system 0.9.0 | 14 / 14 |
| Debian 13 (6.12.95) | system 0.12.0 | 14 / 14 |
| Fedora 44 (6.19.10, SELinux enforcing) | system 0.12.0 | 14 / 14 |
| Ubuntu 26.04 (7.0.0) | system 0.11.1 (`bwrap-userns-restrict`) | 14 / 14 |
| Ubuntu 26.04 | escrowd bwrap + `escrowd_bwrap` profile | 14 / 14 |
| Ubuntu 24.04 (6.8.0) | system 0.9.0, no profile | 3 / 14; bwrap fails at `setting up uid map: Permission denied` |
| Ubuntu 24.04 | escrowd bwrap + `escrowd_bwrap` profile | 14 / 14 |

The 14 checks: unprivileged mount through `fusermount3`; view at the project path inside bwrap; read; bash redirect, heredoc and python writes; rename and delete; `git init`, commit and clean status; nested user namespace blocked; daemon hidden by the pid namespace; writes reached the base; a view mounted over its own base path serves reads and writes (pre-opened base, no loop); daemon death seen in the sandbox as ENOTCONN.

Extra probe, Ubuntu 24.04 and 26.04, escrowd bwrap without `--disable-userns`: sandboxed processes run as `escrowd_bwrap//&escrowd_unpriv_bwrap (enforce)` and `unshare -Urm` fails with `Operation not permitted`. Nested namespaces are blocked twice: by bwrap's `--disable-userns` on every host, and by the AppArmor child profile on Ubuntu.

Findings:

1. Ubuntu 26.04 confines `fusermount3` with AppArmor: FUSE mounts only under `$HOME`, `/mnt`, `/run/user/<uid>`, `/media`, `/tmp`. escrowd's views must live under `$XDG_RUNTIME_DIR`.
2. Base access through `/proc/self/fd/<O_PATH fd>/<rel>` never resolves through the mount; the root must be addressed as `<fd>/.`, since `lstat` on the bare magic link returns the link.
3. A path-keyed inode table must re-key renamed entries exactly (no trailing slash); git's lockfile-then-rename writes exposed the bug.
4. Lima's 9p home mount (`cache=loose`, Ubuntu 26.04 VM) serves stale files after host edits; drop the VM page cache before each run.
