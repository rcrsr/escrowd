# 0.1 Host matrix

Readings per host, taken inside each Lima VM built from `spikes/lima/`. One section per host; newest reading first.

## Summary, Oct 3, 2026

| Host | Kernel | LSM in charge | Userns restriction | bubblewrap | fusermount3 | `unshare -Urm` + mount | Stock bwrap + mount |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Ubuntu 24.04.4 LTS | 6.8.0-134-generic | AppArmor | `restrict_unprivileged_userns=1`, no bwrap profile | 0.9.0 | 3.14.0 | Fails at uid_map | Fails at uid map |
| Ubuntu 26.04 LTS | 7.0.0-28-generic | AppArmor | `restrict_unprivileged_userns=1`, `restrict_unprivileged_unconfined=1`, `bwrap-userns-restrict` loaded | 0.11.1 | 3.18.2 | Fails at uid_map | Namespace created; mount inside fails (children capability-stripped) |
| Debian 13 | 6.12.95+deb13-cloud-amd64 | AppArmor | None | 0.12.0 | 3.17.2 | Works | Works |
| Fedora 44 | 6.19.10-300.fc44 | SELinux, enforcing | None | 0.12.0 | 3.18.2 | Works | Works |

Every host has `/dev/fuse` at 0666 and a setuid-root `fusermount3`. The Ubuntu 24.04 cloud image ships neither bubblewrap nor fuse3; the other VMs ran provisioning at first boot, so whether their images include them is not recorded.

Findings:

1. Only Ubuntu restricts user namespaces. Debian runs AppArmor without the restriction; Fedora's enforcing SELinux does not block unprivileged bwrap.
2. Ubuntu 26.04 confirms the `bwrap-userns-restrict` model: `/usr/bin/bwrap` gets its namespace, but what it runs cannot mount even with `--cap-add ALL`. Our own bwrap needs its own profile on both Ubuntu releases; the stock profile covers only `/usr/bin/bwrap`.
3. Ubuntu 26.04 also sets `restrict_unprivileged_unconfined=1` (0 on 24.04).

Checks:

| Check | Result |
| --- | --- |
| `unshare -Urm` then `mount -t tmpfs` | Fails: `write failed /proc/self/uid_map: Operation not permitted` |
| `bwrap --unshare-user --cap-add ALL` then `mount -t tmpfs` | Fails: `bwrap: setting up uid map: Permission denied` |

Finding: on stock 24.04, unprivileged bwrap fails before any mount, at uid-map setup. This is the case the AppArmor profile in `docs/phase-0-spikes.md` must fix; 0.2 re-runs the bwrap check with the profile loaded.
